# MEMEFinder 项目概述

## 1. 项目简介

MEMEFinder 是一个功能强大的本地表情包管理和搜索工具，旨在帮助用户通过文字搜索快速找到本地存储的表情包。它利用 OCR（光学字符识别）技术提取图片中的文字，并结合情绪分析、自定义标签、收藏管理等功能，实现智能化的表情包管理和检索。

**核心功能：**
*   **本地图源管理**：支持添加多个本地文件夹作为表情包来源
*   **智能 OCR 识别**：自动扫描并识别图片中的文字内容（基于 RapidOCR）
*   **情绪分析**：对识别到的文字进行情绪分析（正向/负向/中性），辅助搜索
*   **自定义标签系统**：创建彩色标签，为图片分类管理
*   **收藏功能**：一键收藏常用表情包，快速筛选
*   **批量操作**：右键菜单支持批量编辑标签、情感、收藏状态等
*   **快速搜索**：支持关键词搜索和多维度筛选（情感、图源、收藏、标签）
*   **隐私安全**：所有处理均在本地完成，无需联网上传图片

## 2. 技术栈

*   **编程语言**: Python 3
*   **GUI 框架**: Tkinter (Python 内置)
*   **数据库**: SQLite 3
*   **OCR 引擎**: RapidOCR (基于 ONNXRuntime)
*   **情绪分析**: SnowNLP (中文) / TextBlob (英文)
*   **打包工具**: PyInstaller

## 4. 模块功能详解

### 4.1 核心模块 (`src/core`)

负责应用程序的主要业务逻辑，包括数据存储、图像处理和算法分析。

*   **`database.py` (数据库管理)**
    *   管理 SQLite 数据库连接池。
    *   定义数据表结构：
        *   `image_sources`: 存储图源文件夹路径及扫描状态。
        *   `images`: 存储图片信息、OCR 识别结果、情绪分析结果。
        *   `app_state`: 存储应用配置和断点续传状态。
    *   提供增删改查接口，支持批量操作以优化性能。

*   **`scanner.py` (文件扫描)**
    *   扫描指定目录下的图片文件。
    *   支持多种图片格式（jpg/png/bmp/webp/gif/tiff）。
    *   计算文件 MD5 哈希值，避免重复处理。

*   **`ocr/` (OCR 模块 - 模块化设计)**
    
    OCR 模块采用模块化设计，职责清晰分离：
    
    *   **`ocr_engine.py` (OCR 引擎)**
        *   封装 `RapidOCR` 库。
        *   支持 GPU 加速（自动检测 CUDA/DirectML）和 CPU 模式回退。
        *   提供图片文本检测和识别功能。
        *   包含图像预处理（如 Padding）以提高边缘文字识别率。
    
    *   **`processor.py` (OCR 处理器)**
        *   整合 OCR 引擎、文本处理、情感分析功能。
        *   实现完整的图片处理流水线：读取图片 → OCR 识别 → 文本提取 → 文本过滤 → 情感分析。
        *   支持延迟加载模型，优化内存使用。
        *   集成资源监控，定期执行垃圾回收。
        *   提供向后兼容接口。
    
    *   **`sentiment_analyzer.py` (情感分析)**
        *   提供文本情绪倾向分析。
        *   **多引擎支持**：
            *   `SnowNLP`: 针对中文文本的情绪分析（默认，懒加载）。
            *   `TextBlob`: 针对英文文本的情绪分析。
            *   `Keyword`: 基于关键词库的简单规则匹配（作为回退方案）。
        *   输出情绪类别（正向/负向/中性）及置信度分数。
    
    *   **`text_processor.py` (文本处理)**
        *   从 OCR 结果中提取文本。
        *   文本清洗功能：
            *   过滤网址（http、https、www、.com 等）。
            *   过滤常见水印关键词（微信、抖音、小红书等）。
            *   过滤特殊符号和多余空格。

### 4.2 界面模块 (`src/gui`)

基于 Tkinter 构建的用户界面，采用模块化设计。

*   **`main_window.py` (主窗口)**
    *   应用程序的主框架。
    *   管理标签页切换和全局状态。
    *   处理断点续传逻辑。

*   **`source_tab.py` (图源管理页)**
    *   展示和管理图片来源文件夹。
    *   提供添加、删除、启用/禁用图源的功能。
    *   显示各图源的图片数量和扫描状态。

*   **`process_tab/` (图片处理页 - 模块化协调器)**
    
    采用职责分离原则，拆分为多个独立模块：
    
    *   **`process_tab.py`** - 主协调器
        *   整合各子模块，提供统一接口
        *   管理处理流程的生命周期
    
    *   **`process_tab_ui.py`** - UI 组件创建和布局管理
        *   负责所有界面元素的创建和布局
        *   进度条、日志显示、控制按钮等
    
    *   **`process_tab_models.py`** - OCR 和情感分析模型管理
        *   模型下载、检查和加载
        *   模型状态管理
    
    *   **`process_tab_gpu.py`** - GPU 状态检测、安装和配置
        *   GPU 硬件检测
        *   CUDA 环境配置
        *   GPU 支持库安装
    
    *   **`process_tab_processor.py`** - 图片处理核心逻辑
        *   单线程/多线程处理模式
        *   批量处理和进度追踪
        *   资源监控和优化
    
    **主要功能**：
    *   控制图片扫描和 OCR 处理任务
    *   显示实时处理进度、日志和资源使用情况
    *   支持暂停、恢复和停止处理
    *   支持 GPU 加速（可选）
    *   支持多线程并行处理

*   **`search_tab.py` (图片搜索页)**
    *   提供搜索界面：关键词输入框、情绪筛选下拉框。
    *   以瀑布流或网格形式展示搜索结果。
    *   支持预览大图、复制图片、打开文件位置等操作。
    *   实现分页加载，优化大量图片展示时的性能。

*   **`loading_window.py` (加载窗口)**
    *   程序启动时的初始化界面。
    *   负责后台加载模型文件，避免界面卡顿。

### 4.3 工具模块 (`src/utils`)

提供各种通用工具和辅助功能。

*   **`logger.py`**: 统一的日志记录配置。
*   **`resource_path.py`**: 资源路径管理工具
    *   提供 `get_resource_path()` 函数，统一处理开发环境和打包环境的资源文件路径
    *   提供 `get_icon_path()` 函数，自动查找应用图标
    *   支持 PyInstaller 打包后的 `sys._MEIPASS` 临时目录
*   **`model_manager.py`**: 管理 OCR 和情感分析模型的下载、检查和安装。
*   **`gpu_detector.py`**: 检测系统 GPU 硬件和驱动状态，提供 GPU 推荐信息。
*   **`gpu_installer.py`**: GPU 加速配置工具
    *   负责将系统 CUDA DLL 复制到应用目录
    *   支持 CUDA 11 和 CUDA 12
    *   提供安装状态检测和卸载功能
*   **`cuda_finder.py`**: 自动查找系统中的 CUDA 安装路径
    *   检查常见安装位置
    *   验证 CUDA 版本兼容性
*   **`cuda_validator.py`**: 验证 CUDA 安装路径和版本
    *   确保包含必要的 DLL 文件
    *   验证 CUDA 工具包完整性
*   **`resource_monitor.py`**: 监控系统内存和 CPU 使用率。

### 4.4 打包配置 (`hooks/`)

PyInstaller 自定义 hooks，用于正确打包第三方库的依赖和资源文件。

*   **`hook-onnxruntime.py`**: 
    *   收集 ONNX Runtime 的必要 DLL
    *   排除 CUDA 相关 DLL（使用系统 CUDA，减小打包体积）
*   **`hook-rapidocr_onnxruntime.py`**: 
    *   打包 RapidOCR 库自带的 OCR 模型文件
    *   收集相关数据文件和子模块
*   **`hook-snownlp.py`**: 
    *   处理 SnowNLP 中文情感分析库
    *   当前配置排除数据文件以减小体积
*   **`hook-tkinter.py`**: 
    *   修复 Tcl/Tk 版本冲突问题
    *   收集 Tcl/Tk 运行时库和数据文件

详细说明请参考 [hooks/README.md](../hooks/README.md)。

### 4.5 资源文件 (`assets/`)

存放应用程序的静态资源文件。

*   **`icon.ico`**: 应用程序图标
    *   用于窗口标题栏图标
    *   用于 Windows 任务栏图标
    *   打包后会被包含在发布版本中

## 5. 数据流程

1.  **添加图源**: 用户在 GUI 添加文件夹 → `scanner` 扫描文件 → 存入 `image_sources` 和 `images` 表（状态为未处理）。
2.  **处理图片**: 用户点击开始处理 → `ocr.processor` 读取未处理图片 → 调用 `ocr.ocr_engine` 识别文字 → 调用 `ocr.text_processor` 提取和过滤文本 → 调用 `ocr.sentiment_analyzer` 分析情绪 → 更新 `images` 表（写入结果，标记为已处理）。
3.  **搜索图片**: 用户输入关键词 → `database` 查询 `images` 表（匹配 `ocr_text` 或 `filtered_text`） → GUI 展示结果。
